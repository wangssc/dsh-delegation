# dsh-delegation

**给 AI 配一个打工人。** 主 AI 只做判断、决策、验收，把读长文档、翻代码、跑测试、写测试数据这类体力活，派给另一个便宜或免费的 AI 去做。

装好之后，你说「帮我改一下这个项目」，它不会自己吭哧吭哧读三千行代码——它会先问自己一句：**这活要读多少？超过 200 行就派出去。**

---

## 为什么需要这个

单 Agent 干活有个隐形浪费：**判断力和体力活花的是同一份预算。**

- 读一份 900 行的日志找一个 bug → 花掉的钱和「想清楚这个 bug 该怎么修」一样多
- 但这两件事的价值差 100 倍

这个技能做的事很简单：**把「读」和「想」分开，交给不同的模型。**

| | 主 AI | 打工人 |
|---|---|---|
| 干什么 | 定规格、判断对错、决策、验收 | 读、抄、跑、批量改、造测试数据 |
| 花谁的钱 | 贵的 | 便宜的/免费的 |
| 输出什么 | 结论和决定 | 一句话结论 + 关键数字 + 证据在哪 |

---

## 核心就三条

### 1. 判据是「要读多少」，不是「难不难」

**要读超过 200 行 → 派出去。** 不是「这活难不难」，是「我要不要把一大堆东西装进上下文」。

自己干只在这三种情况成立：
- 需要本会话的上下文（打工人一个字都不知道）
- 需要来回确认（它一次就结束，问不了）
- 要浏览器或图形界面

### 2. 派单给验收标准，不给实现步骤

说清**什么算对**，不替它想怎么做。

> 反例：「你用最小哈希算法，建 16 个带，每带 4 行」
> 正例：「近似查重不能两两全比会跑死，别的你自己想，代价写进 README」

实测：只说「不能两两全比」这半句，打工人自己想了 MinHash + LSH + 并查集，造 400 个文件验证自己，30 个测试全过。

### 3. 验收不能省，但可以用最便宜的方式

**它说「全过了」不算数。** 但也不用通读它的代码——跑能推翻结论的那一条就够。

一条命令、看一个数字、拆开一个文件看一眼。

## 装

```bash
git clone https://github.com/wangssc/dsh-delegation.git
cp -r dsh-delegation ~/.dsh/skills/dsh-delegation
```

Windows:

```powershell
git clone https://github.com/wangssc/dsh-delegation.git
Copy-Item -Recurse dsh-delegation "$env:USERPROFILE\.dsh\skills\dsh-delegation"
```

**不用重启。** DSH 会自己扫到，下一个会话就在技能目录里。

---

## 用

装完之后，正常干活就行。它会：

- **开工前**判断这活该自己干还是派出去
- **派活时**按模板写单子（目标 / 验收标准 / 边界 / 交付形态）
- **收活时**验收，然后跟你说结论
- **汇报时**先给结论（BLUF），给选项不只给方案，风险配缓解

你也可以直接说：「这个派出去」。

---

## 这是技能，不是插件

DSH 有插件系统（cordis 插件，走 npm 或 Git 安装，带编译）。**这个模式不需要那个。**

因为它的本质是**方法**，不是**代码**：
- 插件能给你一个工具，但给不了你「先判断再派」这个习惯
- 技能是提示词，改一次立刻生效，不用发版

如果你确实想要一个 `dispatch(...)` 工具（把派单记进队列、自动重试、汇总回执），那是另一件事，可以做成 cordis 插件。本项目暂时只做方法，不提供代码。

## 不适用

- **单文件小改动**。派单的成本比干活还高。
- **需要大量来回确认的设计讨论**。打工人一次就结束，没法跟你磨。
- **你自己也没想清楚要什么**。验收标准写不出来，说明还没想明白，先别派。
